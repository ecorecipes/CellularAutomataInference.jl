API Reference

Priors

Priors are NamedTuples of continuous univariate distributions from Distributions.jl, independent of each other.

CellularAutomataInference.logprior — Function
logprior(priors::NamedTuple, θ::NamedTuple) -> Float64

The log prior density of the parameters θ: the sum over parameters of logpdf(priors[k], θ[k]), for a NamedTuple of continuous univariate distributions from Distributions.jl. θ must have exactly the parameters of priors, in any order.

source
CellularAutomataInference.rand_prior — Function
rand_prior(rng, priors::NamedTuple) -> NamedTuple

One draw of every parameter from its prior, made with the random number generator rng.

Likelihood-based fitting

sample, MCMCSerial, MCMCThreads and LogDensityModel are re-exported from AbstractMCMC.jl.

CellularAutomataInference.PosteriorDensity — Type
PosteriorDensity(loglik, priors)

A posterior density for the parameters named in priors (a NamedTuple of continuous univariate distributions from Distributions.jl), with log-likelihood loglik(θ) for a NamedTuple θ. It implements the LogDensityProblems interface on the unconstrained scale: each parameter is mapped to the real line by a bijection chosen from its prior's support (logit, log or identity), and the density includes the log-Jacobian, so logdensity at y is the log posterior density of y. constrain and unconstrain convert between the scales. Wrap it in AbstractMCMC.LogDensityModel to sample it.

source

constrain(ℓ::PosteriorDensity, y) -> NamedTuple

The parameters at the point y of the unconstrained scale.

source
CellularAutomataInference.unconstrain — Function
unconstrain(ℓ::PosteriorDensity, θ::NamedTuple) -> Vector{Float64}

The point of the unconstrained scale for the parameters θ.

CellularAutomataInference.AdaptiveMetropolis — Type
AdaptiveMetropolis(; adapt_after=200, init_scale=0.1, epsilon=1e-6)

The adaptive Metropolis sampler (Haario et al., 2001), an AbstractMCMC.AbstractSampler for an AbstractMCMC.LogDensityModel. For the first adapt_after iterations the proposal adds independent normal steps with standard deviation init_scale to every coordinate; afterwards it is normal with covariance 2.38^2 / d * (C + epsilon * I), where C is the covariance of the chain so far and d the dimension. On a PosteriorDensity the chain moves on the unconstrained scale and records the parameters as a NamedTuple.

model = AbstractMCMC.LogDensityModel(PosteriorDensity(loglik, priors))
chain = sample(rng, model, AdaptiveMetropolis(), 10_000; initial_params=θ0)

sample returns an MCMCSamples; with MCMCThreads() and a number of chains, a vector of them. Without initial_params a chain starts from a draw of the prior.

source
CellularAutomataInference.MetropolisTransition — Type
MetropolisTransition

One state of an AdaptiveMetropolis chain: params (a NamedTuple on a PosteriorDensity, otherwise the vector), its logdensity and whether the move to it was accepted.

CellularAutomataInference.AugmentedModel — Type
AugmentedModel(loglik, latent_step!, priors, latent; record=nothing)

A model with parameters (named in priors, a NamedTuple of continuous univariate distributions) and latent variables (unobserved event times, hidden states), for sampling by data augmentation (Gibson and Renshaw, 1998) with DataAugmentation. loglik(θ, z) is the joint log-density of the data and the latent variables z given the parameters θ; latent_step!(rng, z, θ) updates z in place by any move that leaves the conditional distribution of z given θ and the data invariant (Metropolis-Hastings or Gibbs updates of each latent variable, say). latent is the initial latent state, copied for each chain. record(z), if given, is stored at every kept iteration (copy anything mutable).

source
CellularAutomataInference.DataAugmentation — Type
DataAugmentation(; parameter_steps=1, adapt_after=200, init_scale=0.1, epsilon=1e-6)

The sampler for an AugmentedModel: each iteration updates the latent variables with the model's latent_step!, then makes parameter_steps AdaptiveMetropolis moves of the parameters given the latent variables (the other keywords configure them). The chain targets the joint posterior of parameters and latent variables; its parameter columns are a sample from their marginal posterior.

source
CellularAutomataInference.AugmentedTransition — Type
AugmentedTransition

One state of a DataAugmentation chain: params, the joint logdensity of parameters and latent variables, whether any parameter move was accepted, and the model's record of the latent variables (or nothing).

source
CellularAutomataInference.MCMCSamples — Type
MCMCSamples

The output of sample with AdaptiveMetropolis or DataAugmentation: names (the parameters), values (one row per kept iteration, one column per parameter, on the parameters' own scale), logdensity (the log posterior density on the unconstrained scale, up to a constant, or the joint density of parameters and latent variables under data augmentation), acceptance (the share of parameter moves accepted) and records (what an AugmentedModel's record returned at each kept iteration; empty otherwise). chain[:β] is the column of parameter β.

Simulation-based fitting

CellularAutomataInference.abc_smc — Function
abc_smc(simulate, priors, distance, observed; tolerance, nparticles=500, rng,
        parallel=false, verbose=false, kwargs...) -> ABCPosterior
abc_smc(prob::CAProblem, priors, distance, observed; parameters=identity,
        alg=Synchronous(), solve_kwargs=(;), kwargs...) -> ABCPosterior

Approximate Bayesian computation by sequential Monte Carlo with differential-evolution moves, through ABCdeZ.jl's abcdesmc!. priors is a NamedTuple of univariate distributions from Distributions.jl; simulate(θ, seed) simulates data for the parameters θ (a NamedTuple) with the random seed seed, and distance(simulated, observed) is a nonnegative number. The tolerance falls adaptively until it reaches tolerance (or ABCdeZ's other stopping rules apply; extra keywords such as nsims_max, α and Kmcmc pass through to abcdesmc!).

The second form fits a cellular automaton problem: each simulation is solve(remake(prob; p=parameters(θ), seed), alg; solve_kwargs...), and the distance compares that solution with observed.

Each simulation's seed is a hash of its parameter values, so a particle's distance does not depend on the order or thread in which it was computed. rng drives the sampler itself: a run is reproducible with parallel=false and a seeded rng; with parallel=true the threads share rng, which must be thread-safe, and runs are not reproducible.

source
CellularAutomataInference.ABCPosterior — Type
ABCPosterior

The result of abc_smc: names (the parameters), values (one row per particle, one column per parameter), weights (normalised, zero for particles that died; weight the particles when summarising), distances (each particle's distance from the observations), tolerance (the final ABC tolerance), logevidence (the estimated log model evidence at that tolerance, for comparing models fitted to the same data with the same distance) and tolerances (the sequence of tolerances, starting at Inf). post[:β] is the column of β.

Diagnostics

CellularAutomataInference.effective_sample_size — Function
effective_sample_size(x::AbstractVector) -> Float64
effective_sample_size(chain::MCMCSamples, name::Symbol) -> Float64

The effective sample size of a chain of draws, n / τ with the integrated autocorrelation time τ estimated by Geyer's initial monotone sequence (Geyer, 1992): sums of autocorrelations at adjacent lags are added while they are positive and made non-increasing. NaN for a constant chain.

source
CellularAutomataInference.rhat — Function
rhat(chains::AbstractVector{<:AbstractVector}) -> Float64
rhat(chains::AbstractVector{MCMCSamples}, name::Symbol) -> Float64

The split potential scale reduction factor (Gelman et al., 2013) of several chains of the same length: each chain is split in halves, and the between-half variance is compared with the within-half variance. Values near one (below about 1.01 to 1.05) suggest the chains have mixed.

source
CellularAutomataInference.posterior_summary — Function
posterior_summary(chain::MCMCSamples; quantiles=(0.025, 0.5, 0.975)) -> NamedTuple
posterior_summary(chains::AbstractVector{MCMCSamples}; quantiles) -> NamedTuple
posterior_summary(post::ABCPosterior; quantiles) -> NamedTuple

For each parameter, a NamedTuple of its posterior mean, sd, the requested quantiles (as q, the vector of their values) and the effective sample size ess: from the draws of one chain or the pooled draws of several (summing the chains' effective sample sizes, and adding rhat), or from the weighted particles of an ABCPosterior (whose ess is 1 / sum(w .^ 2)).

SupportError(what, value, msg)

Thrown when a sampler would start where the target has no density: a parameter outside its prior's support, or a starting point whose log-likelihood is -Inf or NaN. what names the parameter or quantity and value is the offending value.

Module

CellularAutomataInference — Module
CellularAutomataInference

Fitting cellular automata to data, for models built with CellularAutomataCore.jl.

  • Priors are NamedTuples of continuous univariate distributions from Distributions.jl (logprior, rand_prior).
  • Likelihood-based fitting goes through the AbstractMCMC interface. A PosteriorDensity is a LogDensityProblems object on an unconstrained scale, so AbstractMCMC.LogDensityModel wraps it for AdaptiveMetropolis or any other sampler of that interface; an AugmentedModel with DataAugmentation samples parameters together with latent variables, such as the unobserved infection times between surveys. The core's path_logpdf gives the exact likelihood of a fully observed path, and its observation models score what a survey or sensor reports.
  • Simulation-based fitting is approximate Bayesian computation by sequential Monte Carlo through ABCdeZ.jl (abc_smc), with model evidence for comparing models.
  • effective_sample_size, rhat and posterior_summary summarise the results.

This package depends on CellularAutomataCore.jl and on no other package of the ecosystem.
